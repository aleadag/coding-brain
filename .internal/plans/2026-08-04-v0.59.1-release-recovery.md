> Status: approved for implementation on 2026-08-04
>

## Goal

Recover forward from the immutable failed `v0.59.0` tag by restoring Linux musl compatibility without weakening the permission-journal no-replacement invariant, adding pre-tag regression coverage for both release musl targets, and preparing `v0.59.1` as the first distributable crates.io/GitHub/Homebrew release.

## Grounded Failure

`v0.59.0` passed its tag, credential, collision, formatting, Clippy, and test gates. The release then failed before publication because `src/brain/permission_transaction.rs` selected `libc::renameat2` for every Linux target. The locked `libc 0.2.186` crate declares that function for GNU Linux but not musl; it does expose `libc::syscall` and `libc::SYS_renameat2` for the two release targets.

No crate, GitHub Release, or Homebrew formula was published. The annotated `v0.59.0` tag remains fixed in place and must not be deleted or moved.

## Design Constraints

- Preserve atomic `RENAME_NOREPLACE` journal publication; never fall back to a check-then-rename sequence.
- Keep GNU Linux and Android on their existing direct `renameat2` binding.
- Use the raw kernel syscall only for `target_os = "linux"` plus `target_env = "musl"`.
- Preserve `-1`/`errno` behavior so `io::Error::last_os_error()` remains correct.
- Add no dependency for a single target-specific call.
- Make both `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl` compile on pull requests, before a release tag exists.
- Execute the existing no-replacement behavior test under x86_64 musl, where the test binary can run natively.
- Recover as `0.59.1`; never repoint `v0.59.0` or publish source whose tree differs from its tag.
